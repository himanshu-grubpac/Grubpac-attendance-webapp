1. Getting started

Admin and HR users manage the full Grubpac Attendance system: employees, roles, departments, office geofence, leave policies, company-wide attendance, and support tickets.

  1. Sign in on the Admin tab at d24p2zn8763d4h.cloudfront.net.
  2. Dashboard shows org-wide summaries (open help tickets, pending leave, etc.).
  3. Sidebar sections: Overview, Employees, Leaves, Operations.
HR has nearly full admin access except some system roles. Full Admin has all permissions including role management.

2. Employees & organization

Register & import

  • Register Employee — single employee with department, role, reporting manager.
  • Bulk Import — Excel template with department, reporting manager email/code.
  • Employee List — search, open profile, edit org details, leave balances, salary (if permitted).

Reporting managers & department heads

  • Every Employee role requires a reporting manager.
  • Reporting Manager role should have at least one managed department for department-head scope.
  • Set delegate approver on a manager profile for temporary approval coverage.

Departments & roles

  • Departments — org structure codes (DEV, DES, etc.).
  • Roles & Permissions — system roles (Admin, HR, Reporting Manager, Employee) plus custom roles.

3. Attendance policy (current behaviour)

Configure and communicate these rules to all staff:

RuleSystem behaviour
Check-in UX No Office/WFH toggle — employees check in/out only; server auto-detects mode from GPS + leave.
Office Within geofence → office check-in (OFC / P).
WFH Requires approved WFH leave for that IST day; home check-in allowed when approved.
Other leave Approved CL/EL/SL/RH/etc. blocks check-in for covered dates.
Apply deadline SL anytime; all other types must be submitted before 11:59 PM IST to include tomorrow.
Permanent WFH Not supported as a profile flag — use long WFH approval or manual HR process.

Outcome codes (employee history)

P, OFC, WFH, HD, W1–W3, LV — configure grace/half-day thresholds under Geolocation & Timings.

Attendance history (all employees)

Admin/HR with read all permission can filter any employee. Managers see team scope only.

4. Leave, WFH & calendar

Leave policies

Configure quotas, accrual, carry-forward, and paid/LOP rules per leave type (SL, CL, EL, WFH, CO, RH).

Pending requests

HR/Admin can approve any request in the global queue. Managers approve their reporting lines.

Calendar management

Set company holidays and restricted holidays. Employee dashboards highlight approved leave on the month calendar.

Balance adjustments

Manual balance corrections and year-end carry-forward (admin tools on employee profile / policies page).

Staging deployment

Guides ship with the frontend static assets. After updating guides, redeploy the client to staging so /guides/*.html is available on CloudFront.

7. Troubleshooting

Employee cannot WFH check-in

  • Verify WFH leave is approved for today (IST).
  • Check they applied before cutoff if the date was tomorrow.

Wrong manager in approval chain

Update reporting manager on the employee profile.

Geofence too strict

Adjust radius in Geolocation & Timings; communicate changes to staff.

Long-term remote worker

No permanent WFH mode — approve extended WFH leave or document an offline HR exception.

8. FAQ

Where are user guides stored?

Static HTML in client/public/guides/ — linked from Help and FAQ & Demo pages.

Can I edit guides without a deploy?

Locally yes (npm run dev). Staging/production require a frontend build and S3 sync.

Who sees which guide?

Employee portal → Employee guide. Admin portal → Admin, Dept Head, or Reporting Manager guide based on role and managed departments.
